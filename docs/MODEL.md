# 正式计分与服务规则

计分版本：`scoring-v1`。题库版本：`quiz-v2.1`。

## 数据来源与排名

报告由用户提交的26道题的有效选项生成。综合指数是本问卷的规则分数，不是人口百分位。当前没有经过校准的真实同龄样本，不生成参考人物、假设概率或同龄排名。

接口保留 `rank` 结构以兼容已有报告和页面：`available:false`、`percent:null`，标题展示实际综合指数或有效答案不足说明。旧报告读取、提交重试、历史列表、目标完成与旧分享读取均替换旧排名展示；不会把旧模拟百分位继续返回给客户端。历史报告中的必要依据、指数和完成状态保留，不再单独存储完整作答。

## 计分与缺项

计分只在云函数内，19道P题进入计分，5道I题只用于解释，2道背景题不加减分。

六方面各占1/6。经济底气内部收入0.35、现金储备0.25、偿债余量0.40；现金储备由Q09/Q22等权组成。身体精力内部Q03/Q10均值占0.80、Q21占0.20。其余四方面分别三题等权。Q11达到3小时后封顶；Q21达到每周2—3天后封顶；Q26至少一次成功行动同分。完整数值映射见 `cloudfunctions/peakLifeApi/lib/scoring.js`。

X/Y/N和Q19A不当作0分或满分。先在子指标内归一化，再对有效子指标按原权重归一化。每方面至少2道P题有效，全部至少16道P题有效，才输出综合指数，否则总分为null。总分与方面展示最后才四舍五入。

## 类型与行动

八个类型按固定优先级判定，每个规则引用实际有效答案并返回依据。多规则匹配时保留副标签；没有完整符合的规则时使用生活混合模式。组合解析只引用实际有效答案。完成行动仅持久化完成状态，不改变得分。

## 存储内容

未完成作答仅在本机保存7天，成功提交后清除。完整选项在云函数内用于校验、计分和生成报告，结果记录不保存独立的 `answers` 或已停用的 `contribute` 字段。报告保留指数、类型、必要答案依据、解析和目标状态；依据及解析仍可能包含用户选择的收入、存款等档位。

结果集合保留归属、创建时间、分享撤销版本和报告。幂等集合保留归属、创建时间和SHA-256提交指纹，不保留请求编号明文或答案明文，继续支持重试、改答冲突检查及删除墓碑。

本人读取旧报告、历史列表或同编号重试时，自动清理旧的完整答案和贡献字段。目标完成、分享创建和撤销的写入也使用精简记录。迁移在事务中重新读取当前记录，保留并发目标更新和撤销状态，不恢复已删除记录，不处理其他用户的报告。未再次访问的旧记录不会自动全部清理。

## 云端归属与分享

云函数通过微信提供的OPENID识别归属，客户端不能提交owner或成绩。所有数据库客户端安全规则为禁止读写。提交编号按用户隔离；同一编号的相同提交返回同一报告，答案改变须使用新编号；删除后保留幂等墓碑防止重试恢复报告。

分享使用192位随机令牌，数据库仅保存SHA-256摘要，7天过期。公开白名单仅包含生活类型、解析短句、综合指数、排名状态说明、创建时间和过期时间。撤销通过报告版本使全部旧链接立即失效，删除报告后分享也不可读取。读取旧分享时从所属报告重新生成摘要，不使用旧的排名缓存。新分享文档仅保留报告编号、撤销版本和过期时间，令牌摘要作为文档编号，不再重复存储公开摘要。有效读取旧分享时，在事务内移除旧摘要后从报告生成响应；未读取的旧版本过期或撤销摘要仍需运营清理。接口始终独立检查失效状态。

## 部署入口

`main.js` 与 `lib/` 是源码，运行 `npm run build:cloud` 后生成单文件 `index.js`。本地业务模块及题库均内联，运行时只依赖微信服务端SDK和Node内置模块。入口剥离平台注入的 `userInfo` 与 `tcbContext`，不把它们用于用户归属；其他非业务字段仍严格拒绝。响应包含 `apiVersion`，字段校验失败时只返回非法字段名，不返回字段值。

## 验证范围

`tests/` 为本地自动化验证，使用隔离的内存数据，不写入云数据库，不进入部署目录。`npm run check` 检查语法、路由、事件、题库一致性和客户端权限API。云端集合、索引、权限及真实身份隔离需在实际部署后验收。
