# 参考模型与服务边界登记

模型版本：`reference-engineering-v1`。题库版本：`quiz-v2.1`。登记日期：2026-10-15。

## 这是什么估算

当前没有完成匹配这26道题、回忆期和年龄分组的真实样本校准。以下概率和相关性全部是可审计的**工程先验假设**，用于让首版有稳定、可复现的临时位置估算，不是官方统计、调查结果、全国代表性推断或科学效度认证。没有把国家统计局、CFPS、CHFS的宏观数字伪装为本题选项分布；原方案提到的资料目前仅用于问卷口径的后续核查。

所有可比较的展示必须写“估算超过 X% 的同龄人”，并邻近常驻“参考模型估算，尚未完成真实样本校准”。分享摘要同样携带 `rankNote`。2048是每个年龄组生成的**模拟参考人物数**，不是实际参与人数。贡献数据开关只记录未来校准使用意愿，当前不会改变这套模型或即时排名。未满16岁、年龄未答或可比性不足时不返回百分位。

## 计分、缺项与同分

计分只在云函数内。19道P题进入计分；5道I题只用于解释。六方面各占1/6：先合并方面内部，再合并总体。经济底气内部收入0.35、现金储备0.25、偿债余量0.40；现金储备由Q09/Q22等权组成。身体精力内部Q03/Q10均值占0.80、Q21占0.20。其余四方面分别三题等权。Q11达到3小时后封顶；Q21达到每周2—3天后封顶；Q26至少一次成功行动同分。数值映射以服务端 `lib/scoring.js` 为准，与原题库方案一致。

X/Y/N和Q19A不当作0分或满分。先在子指标内归一化，再对有效子指标按原权重归一化；已知方面允许显示剩余有效信息。综合指数要求每方面至少2道P题有效，且全部至少16道P题有效，否则总分null。总分与方面展示最后才四舍五入，比较使用未取整分数。

参考人物用用户**同一有效题目掩码**重新计算。重算后仅纳入满足可比性且原始得分为有限数值的参考人物；分母是实际合格参考人物数，若没有合格参考则不排名。Q19A也形成缺项掩码。参考模型的条件分布不生成N/X/Y与Q19A，它表示“该题能够回答时”的假设选项分布，不声称适用率或拒答率为0。这样模型比较不会因参考人物自身再次缺项而改变分母。未来实证校准需要单独处理缺项机制与缺失非随机偏差。

严格小于用户原始综合指数的参考人物才计入被超过；同分不算；百分位向下取整。最低可为0%，不保底，不随机加分。

## 联合分布假设

固定种子211015，加年龄选项字符编码×7919；Mulberry32均匀随机数，Box–Muller标准正态，标准正态CDF近似，按下面各题完整分类概率的逆CDF采样。每组2048个人物；缓存与重启生成结果一致。边界概率和为1，单个概率范围[0,1]。

同一参考人物共享一个正态公共因子C；每方面另有独立因子Z_axis。有方面且不是Q12/Q15/Q20的题，潜变量为 `0.25*C + 0.55*Z_axis + sqrt(1-0.25²-0.55²)*Z_question`。同方面潜变量相关0.365，不同方面0.0625。这些是潜变量相关，并非各档实际相关系数。Q03/Q04/Q06/Q10/Q13/Q14/Q16/Q17/Q18的CDF方向翻转，使更有利的财务、时间、恢复与支持状态大体同向。Q12/Q15/Q20和背景在年龄组内独立采样。

这使收入、存款、现金缓冲和偿债余量正向关联；必要事务占用与可用时间反向关联；恢复感与身体活动影响关联；关系消耗与帮助/表达支持关联。**场景边界Q12没有被假定为固定优劣，因此不与“好生活”潜变量绑定**，它只与实际侵占、消耗的用户答案组合用于类型，不将先答应直接判为差。没有假设所有变量相互独立，也没有把同一类财务问题重复算作多个方面权重。仍未包含家庭结构、地域、职业和年龄段内的进一步异质性。

年龄只选择分布，不直接加分。先验采取以下可质疑的工程趋势：16—24岁收入/现金储备较低、在校比例较高；中年现金储备略高；较高年龄组身体影响概率上移、时间余量上移、退休比例提高。所有其他未覆盖的年龄差异保持同一基础概率，避免假装拥有更多精确信息。生活身份不进入评分。

可复查接口：`referenceProfiles(age,{dependency:.25|.55|.75})`、`scoreAnswers(answers).rawAxes/rawScore`、`rankAnswers(answers)`。诊断中的原始方面权重和原始分不发送到客户端。自动测试覆盖概率和、缺项同掩码、同分严格小于、可比性门槛、确定性与精度。

## 类型与行动

八个类型按原方案优先级依次判定：人生满配，电量告急 → 人间客服 → 脑内加班员 → 计划界劳模 → 低电量硬撑员 → 缓冲区守护者 → 生活有自己的班表 → 临场补丁师。每个规则引用2—3条或以上实际有效答案，并返回题号、题目和所选文字。persona.tags按相同优先级保留所有命中标签（含主类型），每项只含key/title/line/evidence；主类型仍取第一项，其他可作为副标签，公开分享不包含标签或证据。未完整满足时返回生活混合模式，不强行贴标签。未知不触发规则。解释只描述当前回忆期，不诊断健康、人格、智力或成长经历。解释优先选择收入与储备、时间与侵占、恢复与负担、实际帮助与表达、进展与启动等具体组合；每段至少两条有效回答，随后给有条件的解释。空位才使用两条当前观察的中性摘要，答案不足时少展示。

小行动优先从学习启动、延后承诺、结束小事、查储备范围中选择一件；否则给中性两分钟记录。完成行动只将goal.done置true，不改总分、方面分、百分位或模型版本。

## 服务端身份、隐私与幂等

只使用 `cloud.getWXContext().OPENID`，无需昵称头像手机号，无登录页或资料授权。event中的owner、score及未知字段全部拒绝。原始答案只保存在拒绝客户端直读的 `peak_life_results`，用于本人报告、证据和未来同意校准；不通过历史列表或分享接口返回。

三个集合必须手动创建并设客户端读/写均false：`peak_life_results`、`peak_life_requests`、`peak_life_shares`。`peak_life_results`历史查询需要owner升序、createdAt降序、_id升序的联合索引。仅云函数原生wx-server-sdk通过服务端权限读写。提交以 `SHA256(OPENID + NUL + requestId)` 作为事务内唯一文档键，指纹使用按题库顺序规范化的answers、quizVersion和contribute。并发同一请求只产生一份报告；复用编号更改答案或意愿返回IDEMPOTENCY_CONFLICT。请求编号应在客户端重试期间保持。

删除结果移除原始答案和报告，同时令分享引用失效。幂等记录保留owner、不可逆提交指纹与时间，防止网络重试恢复已删除结果；重复旧编号返回RESULT_DELETED。它不含原始答案。若需彻底清理幂等元数据，需增加明确的账户数据清理策略，并让旧客户端请求编号失效。

分享使用crypto.randomBytes(24)，即192位随机令牌；DB仅以SHA256(token)存储，令牌不写DB、不记录日志。公开白名单仅personaTitle/personaLine/score/rankHeadline/rankNote/createdAt/expiresAt。有效期7天；撤回增加结果shareEpoch，使所有旧分享立即失效，之后可重新创建；删除结果同样失效。不公开收入、存款、健康答案、方面详情、证据、OPENID或姓名。过期/撤回分享文档虽暂留DB，仅含最小摘要且无法通过接口读取；生产应安排存储层过期清理，不能以TTL清理是否及时代替接口校验。

## SDK与验证边界

wx-server-sdk固定4.0.2（2026-10-15 npm查询的稳定版），带package-lock.json。已检查实际安装源：事务支持collection.doc.get/set/remove、返回回调结果、冲突重试；原生文档get的不存在情况不会与传输失败混淆，写回去掉_id/_openid等只读元数据。测试使用可注入仓储模拟，并覆盖原生适配层分页和事务调用；尚未配置真实微信云环境，因此不把本地测试声称为云端部署验收。

实际`npm audit`发现SDK传递依赖6项（5 high、1 moderate），主要涉及旧CloudBase的lodash.set/unset及axios；查询时@cloudbase/database最新版仍1.4.3、lodash.set最新版4.3.2，没有可直接替换的官方修复链。未用不兼容强制升级或旧SDK降级掩盖风险。服务端不把用户输入用作SDK路径/URL，所有题号和操作严格白名单；部署仍应关注官方SDK安全更新。运行`node --test tests/cloud*.test.js`复查本地行为，真实环境还需验证云函数权限、集合规则、索引、并发冲突、过期与撤回。
